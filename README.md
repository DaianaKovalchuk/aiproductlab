## LLM Hallucination Checker

Интерактивный веб‑инструмент на Python/Streamlit, который:

- **оценивает риск галлюцинаций** в ответе LLM (ChatGPT, Grok и др.) на основе семантической согласованности с исходным вопросом;
- выполняет **фактологическую проверку** — автоматически извлекает исторические события, даты, имена собственные и сверяет их с Wikipedia;
- предоставляет **детальный разбор** каждого предложения с метриками риска и результатами верификации.

Целевая аудитория: студенты, журналисты, исследователи и все, кто работает с текстами, сгенерированными ИИ, и хочет быстро оценить их достоверность.

## Структура проекта

- `app.py` — одностраничное Streamlit‑приложение (UI, обработка ввода, семантический анализ, факт‑чекинг, визуализация результатов).
- `requirements.txt` — зависимости Python.
- `.env` — опциональный файл с переменными окружения.

## Установка и запуск локально

### 1. Подготовка среды

Требуется Python 3.10+.

```bash
cd путь/к/папке/проекта
python -m venv .venv
# Активация:
# Windows:
.venv\Scripts\activate
# Linux/Mac:
source .venv/bin/activate

pip install -r requirements.txt
```

### 2. Настройка переменных окружения (опционально)

Для расширенного поиска можно использовать Serper.dev, но инструмент полноценно работает и без него, опираясь только на Wikipedia.

```bash
# Скопируйте и настройте при необходимости
SERPER_API_KEY=ваш_ключ_из_serper
```

### 3. Запуск приложения

```bash
streamlit run app.py
```

После запуска интерфейс будет доступен в браузере по адресу `http://localhost:8501`.

## Как пользоваться

1. В поле **«Your Question»** вставьте ваш исходный запрос к LLM.
2. В поле **«AI Response»** вставьте полный ответ модели.
3. Нажмите кнопку **«Analyze Response»**.

Приложение выполнит анализ и покажет:

### 📊 Общие метрики
- **Risk Meter** — итоговый риск галлюцинаций (0–100%) с цветовой индикацией:
  - 🟢 **Low Risk** (<30%) — ответ хорошо согласуется с вопросом
  - 🟡 **Moderate Risk** (30–60%) — рекомендуется выборочная проверка
  - 🔴 **High Risk** (>60%) — высокий риск галлюцинаций
- **Quick Stats** — количество предложений, распределение по уровням риска, число верифицированных фактов

### 📝 Детальный разбор предложений
Для каждого предложения отображается:
- текст предложения;
- **Risk Level** и **Risk Score**;
- **Similarity** — семантическая близость к вопросу;
- краткий анализ;
- при наличии фактологического содержания — раскрывающийся блок с деталями:
  - статус верификации (confirmed / questionable / no_data);
  - уверенность (confidence);
  - извлечённые сущности и даты;
  - ссылка на источник в Wikipedia.

### 📈 Визуализация
- **Response Coherence Overview** — гистограмма распределения семантической близости предложений к вопросу с разбивкой по трём зонам:
  - 🔴 низкая схожесть (<40%);
  - 🟡 средняя схожесть (40–70%);
  - 🟢 высокая схожесть (>70%).

## Семантический анализ

Модуль использует мультиязычную модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` с автоматическим fallback на другие модели при необходимости.

**Алгоритм:**
- разбиение ответа на предложения;
- очистка предложений от маркеров списка (1., 2., 3. и т.д.);
- построение эмбеддингов для вопроса и каждого предложения;
- расчёт косинусного сходства;
- вычисление риска как `(1 - similarity) * 100`;
- агрегация итогового риска (среднее взвешенное).

---

## Фактологическая проверка

Факт-чекер работает с очищенными от маркеров списка предложениями.

**Основные шаги:**

1. **Извлечение сущностей и дат**
   - поиск дат по нескольким паттернам (годы, полные даты);
   - проверка по словарю известных исторических событий и личностей;
   - выделение слов с заглавной буквы внутри предложения.

2. **Формирование поисковых запросов**
   - комбинации сущностей с датами;
   - отдельные сущности;
   - даты с контекстом ("события 988 года").

3. **Поиск в Wikipedia**
   - специальная обработка для известных событий (например, «Крещение Руси»);
   - увеличенный таймаут (10 сек) и повторные попытки при ошибках;
   - оценка релевантности результатов по заголовку и сниппету.

4. **Определение статуса**
   - **confirmed** — высокая релевантность и совпадение ключевых слов;
   - **questionable** — частичное совпадение;
   - **no_data** — источники не найдены или низкая релевантность.

## Обработка ошибок и граничные случаи

- **Пустой вопрос/ответ** — пользователь получает понятное сообщение об ошибке.
- **Сбой семантического анализа** — перехватывается с выводом информативного сообщения.
- **Таймауты Wikipedia** — автоматические повторные попытки (до 2 раз) с увеличивающейся задержкой.
- **Отсутствие сущностей в предложении** — предложение не отправляется на факт-чек.
- **Маркеры списка** — автоматически удаляются перед анализом, но сохраняются в отображении.

## Как разворачивать публично

Рекомендуемый способ — **Streamlit Community Cloud**:

1. Создайте репозиторий на GitHub (без файла `.env`).
2. Зайдите на [share.streamlit.io](https://share.streamlit.io) под своим GitHub‑аккаунтом.
3. Создайте новое приложение, указав репозиторий и `app.py` как основной файл.
4. При необходимости добавьте переменные окружения в разделе **Secrets**.
5. Получите публичную ссылку вида `https://имя-приложения.streamlit.app`.
